Payment Received — ask an admin

Every screen, chip and card of this change, phone by phone, taken from the bot's own code word for word. Test it on your phones and tick each step.
What is new

1. After “How was it paid?”, a new screen: “Who should approve it?” Abdul taps one admin, or 👥 Any admin.

2. Only the admin he picks gets the card first. The other admins still find it in 🛂 Approvals.

3. If Abdul does not know the amount, he taps ⏭ Amount not known. The first admin types it; the second admin checks it.

4. If the admin does not answer within the wait time (4 hours unless Krishna changed it), the next reminder goes to every admin.

Who is who
AbdulLagos office manager · employee · records the payment
Musaadmin · the admin Abdul asks first
Krishnaowner · admin · gives the other approval

In this guide customer ABBA owes 120,000. She pays 50,000 into Zenith. Two admin approvals are needed before her balance moves — this does not change.

Names, banks, customers and figures on your phone will differ from this guide. The words and buttons must match.

Before you test
  • Abdul's department must have the tile payment_received (Departments sheet, allowed_activities).
  • At least two admin ids in the Railway ADMIN_IDS list besides the person who records the payment. An admin made only in the Users sheet does not count. With fewer, the bot skips the “Who should approve it?” screen.
  • Each admin needs a name in the Users sheet (or the chip shows Admin and the last 4 digits of the id), and must have opened the bot once, so the bot can send them cards.
  • The bank must be listed in 🏦 Manage Banks.
  • Krishna: read the box For Krishna — prepare before the test on page 2 first.

For Krishna — prepare before the test (owner only)

1. Real records. Parts 1 and 2 each record a real customer payment (Part 3 too, if Musa gives the second approval at the end). Use a test customer, or a very small amount (for example 10) in place of 50,000. The bot has no button to undo a recorded customer payment: decide before the test how the ledger will be corrected.

2. Clean-up. At the end, Musa approves or rejects the Part 3 request, and an admin rejects the request from the Note (👥 Any admin) in 🛂 Approvals.

3. Remind approvers works once per 24 hours for one request (Settings REQUEST_NUDGE_HOURS).

4. Part 3 timing. The bot re-sends waiting cards in rounds every APPROVAL_REMINDER_HOURS (6) hours — counted from the bot's last round since it started, not from the request (REMINDER_HOURS_ADMIN wins when that row has a value). A request asked of one admin waits on that admin alone for ASKED_ADMIN_WIDEN_HOURS (4); the bot checks that wait every hour, so Krishna's card (step 18) comes in the hour after 4 hours. If the first reminder round falls after 4 hours there is no Musa-only reminder (step 16).

To finish Part 3 in about 3 hours: set APPROVAL_REMINDER_HOURS = 1 (and REMINDER_HOURS_ADMIN = 1 if that row has a value) and ASKED_ADMIN_WIDEN_HOURS = 2. Set them back after the test. While the reminder is 1, every waiting request younger than 14 days is re-sent each hour. If the reminder value is 0, no reminder round comes and step 16 cannot be tested; Krishna's card in step 18 still comes after the wait time.
